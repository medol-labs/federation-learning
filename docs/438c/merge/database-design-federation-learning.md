#### 联邦学习模块数据库级设计决策

联邦学习采用按部署单元分布的数据存储。平台、参与方运行时代理及共享支撑服务分别维护本服务的数据；平台与参与方不共享数据库连接。以下决策仅适用于联邦学习模块，不替代总稿中其他模块的数据库设计。

| 设计标识 | 决策主题 | 联邦学习设计决策 |
| --- | --- | --- |
| FL-DB-D01 | 输入与输出 | 应用通过业务命令追加事件，通过查询接口读取视图；数据库不直接向浏览器或其他子系统开放连接。模型工件以引用与文件内容分开保存。 |
| FL-DB-D02 | 响应与一致性 | 事件追加后查询视图异步更新；命令受理与视图可见不保证同时发生。查询应按权限和筛选条件在数据库侧执行，返回分页和总条数。 |
| FL-DB-D03 | 存储形式 | UmaDB 保存业务事件；各服务 PostgreSQL 保存查询视图和事件处理位置；模型、上传文件和参与方数据集不作为关系表中的大字段存储。 |
| FL-DB-D04 | 安全边界 | 数据库连接凭据按服务隔离；原始医疗数据保留在机构本地。查询授权由应用层落实，数据库备份及工件备份分别保护。 |
| FL-DB-D05 | 分布与完整性 | 跨服务以组织、运行时、作业、轮次及工件标识关联，不建立跨数据库外键。事件流是业务状态事实来源，查询视图可从事件重建。 |
| FL-DB-D06 | 备份与恢复 | 分别备份 UmaDB、各服务 PostgreSQL 及文件工件；恢复后核对事件处理位置、关键视图、工件引用及参与方本地数据可用性。 |
| FL-DB-D07 | 空间与索引 | 事件、查询表、索引和文件工件分别规划容量；查询索引以实际筛选条件和执行计划确定。保留、归档与恢复时长由交付环境验证，不虚构固定阈值。 |

联邦学习模块的持久化对象分为业务事件、查询视图和文件工件三类。业务事件记录组织、联邦、运行时、特征架构、训练作业、轮次、模型更新及模型发布等状态变化；查询视图按页面和调度用途组织，供检索与展示；模型文件、上传文件和参与方本地数据集通过工件标识或路径引用，不存为事件负载或普通查询表中的大字段。

平台、参与方代理和共享支撑服务各自持有独立的事件流及查询库。组织和联邦属于平台管理范围；参与方数据集和本地轮次执行状态属于运行时代理管理范围；文件、字典和平台侧身份管理属于共享支撑范围。跨服务关系由组织、运行时、作业、轮次、执行计划和工件标识建立，不设置跨数据库外键。原始医疗数据保留在参与方，不纳入平台集中库。

概念关系为：联邦包含参与组织；组织关联运行时；训练配置引用特征架构和初始模型；训练作业包含多个轮次；每轮为选中的运行时生成执行计划；执行产生模型更新，聚合与评估后形成全局模型。事件流与查询视图都反映这些业务关系，但事件流是状态变化的事实来源，查询视图是可重建的派生数据，不将二者画成同一张 E-R 表。

目录查询先限定用户可访问的数据范围，再根据字段类型组合筛选条件。列表数据与总条数统计使用相同的授权和筛选条件；分页排序需要稳定的次序，避免同值记录跨页重复或遗漏。按标识查详情也应检查访问范围。训练作业、轮次、运行时、组织、数据集和状态等常用条件应结合实际执行计划建立索引，不能仅凭字段存在就宣称查询性能达标。

当前联邦学习部署使用 UmaDB 保存事件，PostgreSQL 保存各服务的查询视图及处理位置。平台、参与方代理和共享支撑服务使用分别配置的存储实例或数据库；不能将“全系统只有一份主数据库文件”的描述套用于本模块。事件存储与关系型查询库的备份、监控和恢复是两条独立链路。

| 存储对象 | 物理载体 | 恢复要求 |
| --- | --- | --- |
| 业务事件 | UmaDB 持久化卷 | 保持事件顺序、业务标签和元数据；恢复后验证追加与读取 |
| 查询视图 | 各服务 PostgreSQL 数据库 | 按服务恢复或从事件重建，并核对处理位置 |
| 模型与上传文件 | 按部署配置的工件/文件存储目录 | 保留工件引用与文件内容的一致性，不只备份索引记录 |
| 参与方数据集 | 参与方本地受控目录 | 不上传到平台；由参与方负责挂载、访问控制与备份 |
