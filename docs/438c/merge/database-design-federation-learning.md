联邦学习模块的持久化对象分为业务事件、查询视图和文件工件三类。业务事件记录组织、联邦、运行时、特征架构、训练作业、轮次、模型更新及模型发布等状态变化；查询视图按页面和调度用途组织，供检索与展示；模型文件、上传文件和参与方本地数据集通过工件标识或路径引用，不存为事件负载或普通查询表中的大字段。

平台、参与方代理和共享支撑服务各自持有独立的事件流及查询库。组织和联邦属于平台管理范围；参与方数据集和本地轮次执行状态属于运行时代理管理范围；文件上传、字典、通知、数据交换和身份访问管理属于共享支撑范围。跨服务关系由组织、运行时、作业、轮次、执行计划和工件标识建立，不设置跨数据库外键。原始医疗数据保留在参与方，不纳入平台集中库。

概念关系为：联邦包含参与组织；组织关联运行时；训练配置引用特征架构和初始模型；训练作业包含多个轮次；每轮为选中的运行时生成执行计划；执行产生模型更新，聚合与评估后形成全局模型。事件流与查询视图都反映这些业务关系，但事件流是状态变化的事实来源，查询视图是可重建的派生数据，不将二者画成同一张 E-R 表。

当前联邦学习部署使用 UmaDB 保存事件，PostgreSQL 保存各服务的查询视图及处理位置。平台、参与方代理和共享支撑服务使用分别配置的存储实例或数据库；不能将“全系统只有一份主数据库文件”的描述套用于本模块。事件存储与关系型查询库的备份、监控和恢复是两条独立链路。

| 存储对象 | 物理载体 | 恢复要求 |
| --- | --- | --- |
| 业务事件 | UmaDB 持久化卷 | 保持事件顺序、业务标签和元数据；恢复后验证追加与读取 |
| 查询视图 | 各服务 PostgreSQL 数据库 | 按服务恢复或从事件重建，并核对处理位置 |
| 模型与上传文件 | 按部署配置的工件/文件存储目录 | 保留工件引用与文件内容的一致性，不只备份索引记录 |
| 参与方数据集 | 参与方本地受控目录 | 不上传到平台；由参与方负责挂载、访问控制与备份 |

#### 业务事件持久化与重放/FL-DB-E001

注册、修改、状态迁移和训练执行的已接受业务结果追加到所属服务的 UmaDB 事件存储。事件记录保存事件标识、类型及版本、发生时间、业务负载、业务关联标签和消息元数据。组织、作业、轮次、执行计划、运行时和更新提交标识分别用于关联对应业务历史，不以查询表当前值代替历史事实。

事件追加使用读取时的一致性标记检测并发冲突；发生冲突时不得覆盖已有事件。业务事件保存下游消费及状态重建所需快照，模型文件和原始数据集内容不写入事件。查询投影按事件消费并保存处理位置；重放须避免重复触发训练、文件上传及远程接口等外部副作用。查询失败与业务拒绝不能视为已追加成功事件。

#### 文件及模型工件持久化/FL-DB-A001

文件内容保存在部署配置的文件或工件存储目录，关系库保存可查询元数据，事件记录上传、引用、失效、删除及模型注册的生命周期变化。文件标识、模型标识和业务引用相互关联；文件名、媒体类型、大小、摘要、状态及存储引用按相应目录的数据元素定义保存，不将二进制正文写入普通查询字段。

上传成功后才能返回可用引用；模型注册关联已保存的工件。下载先校验身份、权限、引用及生命周期状态，再读取内容。文件写入、事件追加和投影更新跨越不同存储，不依赖跨库事务；中断后按文件标识核对内容和元数据，清理未引用文件前检查引用与保留规则。删除或过期后的引用不得继续作为可下载对象。模型工件及其元数据须成对备份和校验。

#### 身份与权限数据保护/FL-DB-S001

用户、角色、权限、用户角色分配、角色授权和服务账户令牌分别由对应目录保存查询数据，状态变更保存在身份访问管理所属服务的事件存储。权限查询以用户、角色和权限标识关联，不与其他服务建立跨库外键。业务访问必须校验授权范围，不能仅凭查询表中的用户或租户字段认定获得访问权。

密码和令牌原文只用于规定的一次性返回，不写入业务事件、查询投影或审计日志；持久化凭据使用不可逆校验表示。数据库账户按服务隔离，业务查询与运维备份账户分别授权，备份文件同样受访问限制。

#### 接口审计数据关联/FL-DB-S002

联邦机构节点接口的审计记录关联调用身份、发生时间、目标业务、执行结果及追踪标识。已产生事件的业务操作通过 user_id、session_id、correlation_id、causation_id、trace_id 与业务标识关联事件和查询结果；鉴权拒绝、参数校验失败等未产生业务事件的请求由接口日志记录，不以事件存储代替全部接口审计。

日志不记录密码、令牌原文、原始医疗数据或模型文件正文。事件、查询记录和日志按追踪标识联合定位，审计数据的访问及留存按部署安全策略控制。

#### 备份与恢复一致性/FL-DB-R001

备份集合按部署单元包含 UmaDB 事件数据、PostgreSQL 查询视图及处理位置、文件工件和恢复所需配置。备份记录各组件的时间与处理位置；不得用单个查询库备份代替完整恢复集合，备份过程中应控制写入或采用存储支持的一致性快照。

恢复时先恢复事件及文件工件，再恢复查询库与消费位置；查询库与事件位置不一致时，以可用事件重建视图并核对处理位置。对组织、训练作业、轮次和模型目录执行数量及关键状态核对，对工件执行引用解析、存在性和摘要校验。恢复验证通过后再开放写入；重放期间隔离训练调度等外部副作用。恢复时间和可接受数据丢失窗口由运行保障要求确定，本节不虚构数值指标。

PostgreSQL 的字段类型以当前持久化实体和实际建表结果为准；时间、数值、UUID 和可变长度文本使用适合的数据类型。对组织、作业、轮次、运行时和状态的常用筛选条件建立并验证索引。当前迁移脚本尚未覆盖全部查询表，交付前应固化可重复部署的建表、约束和索引迁移。事件存储容量需按事件留存量规划，查询库容量按视图及索引规划，文件工件与数据集容量单独核算。备份恢复演练至少验证：事件可读、投影可继续消费、关键查询结果可核对、工件引用可解析。
