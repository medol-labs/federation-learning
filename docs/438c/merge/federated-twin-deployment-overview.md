## 部署说明

联邦孪生软件平台采用云端与医院侧分工部署的方式。联邦学习平台、大模型服务及通用医疗业务模型推理服务部署在云端；医疗数字人与风险评估等孪生应用按需部署在相应医院。只有部署运行时代理并参与训练的医院才具有针对本院数据及人群适配的个性化模型，模型工件保留在本院。该医院同时部署孪生应用时，可部署本地个性化推理服务供其调用；孪生应用也可按场景调用云端模型。运行时代理按任务协调本地训练引擎完成训练、适配与验证，模型工件和运行中的推理服务分别表示。

孪生应用的部署医院集合与联邦训练参与医院集合可以部分重叠，不要求一一对应，但个性化模型的归属限定于训练参与医院。图中的医院 A、B、C 是部署组合示例，不代表具体医院名称、部署数量或地址：医院 A 部署孪生应用、联邦节点及本地个性化推理服务；医院 B 仅部署孪生应用，不参与训练、不配置本院个性化模型；医院 C 部署联邦节点并保留训练适配产生的本院个性化模型工件，不因此假定其部署孪生应用或在线推理服务。实际医院清单、服务地址及网络接入方式按交付部署配置维护。

| 部署位置 | 组件 | 主要职责 |
| --- | --- | --- |
| 云端 | 联邦学习平台 | 联邦协作管理、训练编排、模型更新聚合与验证、模型工件与版本管理。 |
| 云端 | 大模型服务 | 面向适用场景提供推理能力；不默认属于联邦训练对象。 |
| 云端 | 通用医疗业务模型服务 | 部署适用的通用医学模型，按场景提供患者预测、疾病风险等业务推理。 |
| 部署代理并参与训练的医院 | 本院个性化模型工件 | 保留针对本院数据及人群训练适配的模型，与通用模型分别管理工件和适用范围；不自动等同于在线推理服务。 |
| 同时部署孪生应用并参与训练的医院 | 本地个性化推理服务 | 加载本院个性化模型，供本院孪生业务调用。 |
| 孪生部署医院 | 孪生应用 | 接入授权诊疗与监测信息，呈现医疗数字人、风险评估和管理结果；参与训练并部署本地推理服务时可调用本院模型，否则按场景调用云端模型。 |
| 联邦参与医院 | 运行时代理与本地训练引擎 | 本地数据集绑定与读取、接收任务、执行训练与验证、提交模型更新及指标。 |

## 交互边界

- 云端推理：医院孪生应用按场景调用大模型或通用医疗业务模型服务，传输授权范围内的必要信息并获取推理结果。连线接到模型服务区域表示可选调用区内服务，不表示存在额外公共网关，也不预设大模型与医疗业务模型互相调用。
- 本地推理：限于具有运行时代理并参与训练、且实际部署本地推理服务的医院。本地推理服务加载本院个性化模型，由本院孪生应用调用，请求与结果在院内交互；仅部署孪生应用不构成具有本院个性化模型的条件。运行时代理承担训练协调，本地推理服务承担业务推理，两者职责不同。
- 联邦训练：云端平台下发任务、初始模型与配置；医院代理回传模型更新、训练验证指标和数据集元数据。原始训练数据保留在医院本地，不通过联邦训练链路上传病例明细。
- 院内集成：孪生应用按授权接入院内系统、检测及项目可穿戴设备的信息；运行时代理读取授权的本地训练数据。数据来源框不表示孪生应用与代理共用数据库或用户权限服务。
- 模型交付：通用模型可部署到云端通用推理服务；医院个性化模型由该医院参与的训练与本地适配流程产生，在本院保留工件，并按实际需求部署推理服务。图中以绿色连线标出训练产物关系，不表示训练引擎同时承担在线推理，也不表示已经实现自动发布或适配算法。

“原始训练数据不出院”针对联邦训练链路，本地个性化推理则在院内执行；这两点均不能据此推定云端推理请求不携带患者信息。云端推理所需字段、授权、最小化传输、脱敏与安全措施应按实际业务及部署方案明确，不在图中虚构已落实的具体技术方案。

## 维护

本图以同名 `.drawio` 为唯一编辑来源，按实际部署情况调整组件与医院组合，同步导出 PNG 和 SVG。它是部署架构图，不替代详细网络拓扑、端口清单或医院地址配置。

图例使用原生可编辑符号：云形表示部署环境，组件符号表示运行服务或进程，折角文档表示被加载的模型工件，文档符号表示院内系统或数据来源。模型推理服务与其模型工件分别表示，不把模型文件本身作为服务。院内数据来源不等同于共享数据库，图中不因此新增具体数据库或服务实例；数据库、容器等细节需在实际服务级部署方案确认后展开。

图例和相关通用符号已收录到[统一图库](../../diagrams/project-styles.mxlibrary)，可导入 draw.io 复用。模型工件图形作为相应推理服务的子元素维护，随服务整体移动。
