# 软件体系结构

![联邦孪生平台软件体系结构](../../generated/diagrams/federated-twin-software-architecture.png)

图：联邦孪生平台软件体系结构图

联邦孪生平台的软件由联邦学习协作软件、医疗数字人、风险动态评估与管理及应用模型推理软件组成。联邦学习负责跨机构协同训练和模型工件管理；医疗数字人与风险评估软件负责患者状态展示、预测、仿真和风险管理。两侧通过模型工件交付衔接：训练产生的模型可下载，下载后由应用推理侧部署和调用，不由联邦学习平台直接提供医疗业务在线推理接口。

联邦学习软件分为控制台、平台服务、支撑服务、参与方运行时代理和训练与聚合引擎。控制台通过命令及查询接口访问后端；平台服务执行组织与联邦管理、数据集元数据治理、训练编排、参与者选择、执行计划分发、更新接收和聚合协调。平台依据各参与方登记的端点主动下发执行计划，代理负责本地数据集管理、计划校验、训练协调、状态观察与模型更新上报。训练引擎在医院侧执行本地训练和验证推理，聚合引擎在云端执行聚合作业；图中同一引擎部件表示软件职责复用，不表示医院与云端共享同一进程或存储。

联邦学习采用命令处理、业务事件和查询视图分离的组织方式。各部署单元使用自己的事件存储、查询视图和处理位置，模型与上传文件作为工件管理。IAM、字典、文件及通知等由联邦学习自身支撑服务提供；这些能力不表示与孪生应用共用用户体系、数据库或服务实例。

孪生应用通过自身界面和业务软件提供医疗数字人及风险动态评估与管理能力，接入院内诊疗信息、检测信息和项目可穿戴设备信息，并按业务场景调用模型推理软件。大模型和通用医疗业务模型部署在云端；具有运行时代理并参与训练的医院可保留本院个性化模型，并按实际需要在医院侧部署推理软件。孪生业务数据、用户权限和配置由其自身维护。

软件间的接口承担命令、查询、状态及工件传输。原始训练样本留在医院，联邦训练链路传输任务配置、元数据、模型更新和指标。模型交付不表示自动部署，用户使用反馈也不表示已实现自动评审或自动重新训练。具体接口及鉴权约束在接口设计中展开。
