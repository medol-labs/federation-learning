# 系统体系结构

![联邦孪生平台系统体系结构](../../generated/diagrams/federated-twin-system-architecture.png)

图：联邦孪生平台系统体系结构图

联邦孪生平台采用云端与医院侧分布部署的体系结构。云端配置承载联邦学习平台、支撑服务及聚合引擎的服务器资源，并配置承载大模型和通用医疗业务模型的推理服务器资源。平台管理人员通过浏览器终端访问相应服务。联邦训练形成的模型以工件形式交付，下载后由应用推理侧部署；联邦学习平台本身不作为医疗业务在线推理接口。

医院侧根据实际参与范围配置应用服务器、训练服务器和工作终端。孪生应用服务器承载医疗数字人与风险动态评估及管理功能，面向临床及科研人员提供访问入口；训练服务器承载运行时代理和按需运行的训练引擎，读取本院授权数据，完成训练与验证推理，并保留本院个性化模型工件。只有部署代理并参与训练的医院具有相应个性化模型，同时部署孪生应用的医院可根据需要部署本地个性化模型推理服务。

各医院通过院内网络连接相关服务器、工作终端、既有诊疗信息系统和检测设备。项目建设的可穿戴设备及其接入端作为独立设备来源接入，不归入医院既有业务系统。图中设备来源框表示接入范围，不要求设备直接访问训练服务器；数据经相应接入和授权处理后，分别供本地孪生应用或训练使用，不因此共用业务数据库及权限服务。

云端与医院通过跨站点通信网络连接。联邦训练链路传输任务配置、模型工件、模型更新、元数据和执行状态，原始训练样本保留在医院本地。孪生应用按场景调用云端或本院部署的模型服务；云端推理的数据范围与联邦训练链路分别管理，不能将训练数据不出院理解为所有推理请求均不携带患者信息。

医院 A、B、C 表示同时部署、仅部署孪生应用和仅参与联邦训练三种组合，不代表实际医院名称或数量。服务器框表示计算资源的逻辑分组，可落在物理服务器或虚拟化资源上，不限定单机数量、设备品牌或具体配置。部署节点清单和容量配置由相应环境的部署方案确定。
