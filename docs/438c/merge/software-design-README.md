本目录的 `software-design-federation-learning.md` 是联邦学习章节的受控合并源。它对应总软件设计说明中的九处插入点，覆盖设计决策、数据库概念/逻辑/物理设计、体系结构、执行方案、性能、接口和详细设计。数据库查询目录清单从当前 `.medol/codegen-model.json` 读取，仅列平台和参与方代理的实际业务视图；共享支撑目录由系统管理章节统一处理。

总文档位于 `../../../../tmp/merge/项目文档v0.2/02“感一通一算”一体化的跨域健康管理联邦孪生平台-软件设计说明v1.0.docx`。原始文件不受脚本修改。执行：

```bash
python3 scripts/merge-438c-software-design.py --check
python3 scripts/merge-438c-software-design.py
```

第二条命令将合并副本写到 `docs/generated/438c/merge/software-design-federation-learning-merged.docx`。该路径是忽略的生成物，不作为人工编辑源。合并脚本要求九处标题与预期一致，并拒绝覆盖原始总文档或对已合并副本重复插入；总文档改版时先核对锚点，再审阅差异。新增正文的调整应先回填本目录的 Markdown。

## 仍需总文档核对

- 原稿的全局数据库段落写了海量数据库 M100、“一份主数据库文件”等；联邦学习当前实现使用独立的 PostgreSQL 查询库和 UmaDB 事件存储。总文档应区分不同子系统，不得把全局描述误套到联邦学习。
- 原稿的通用性能段落含缓存、NoSQL、CDN、两阶段/三阶段提交等方案；这些不能自动视为联邦学习已实现能力。联邦学习的可验收量化指标仍需目标环境压测确认。
- 原稿的图表、表号、自动章节编号和其他子系统内容保留不动。联邦学习章节合并后，需要在最终 Word 中更新目录、图表题注和交叉引用，并与其他团队确认共享能力的唯一归属。
- 开发环境和交付环境的服务地址及网络可达性不同，设计正文不写死具体 IP、端口或镜像仓库地址；部署参数由对应环境的安装文档确定。
