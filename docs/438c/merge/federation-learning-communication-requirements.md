## 用途与范围

本图用于需求规格说明“计算机通信需求／LBLS-ZY-TX”的联邦学习部分，表达必须互联的网络域、业务调用发起方向、跨域信息范围和院内数据边界。医院 A、B 代表不同训练参与机构，不表示实际医院清单或限定参与数量。

它与[总体部署架构](federated-twin-deployment-overview.md)的区别是：部署图说明组件运行位置，本图说明跨网络必须支持的通信关系。不在此规定具体 IP、端口、网关产品、VPN、运营商线路或容器内部网络，也不直接复用包含这些配置的 operations 实施拓扑。

图中的“通信边界”是受控接入的逻辑边界，不代表已选定或已实现独立网关、代理服务或防火墙产品。“跨域网络通道”表示医院与云端经批准的互联条件，实际接入技术和安全措施由项目及医院网络方案确认。

## 建议需规正文

联邦学习平台与各参与医院的运行时代理通过经批准的跨域网络通道进行通信。云端与医院网络边界应支持所需业务接口的受控访问：平台可向指定医院代理发起训练任务与轮次配置下发，医院代理可向平台发起运行状态、训练指标、数据集元数据及模型更新提交，并按接口约定完成模型工件的获取或上传。两个方向的业务调用应分别满足可达要求，不能仅依据医院可访问云端就认定平台可以访问医院代理；本方案不以医院周期性拉取任务替代平台下发。

医院代理与本地训练引擎之间的任务协调、执行结果获取，以及训练引擎对本地训练数据的读取，应在相应医院的受控环境内完成。原始训练数据不通过联邦协作链路出院，各医院之间不要求建立直接通信或共享数据库连接。模型更新、训练指标和元数据的跨域传输仍须遵循相应安全要求，不因其不是原始病例而默认无需保护。

跨域接入应支持按医院区分通信端点，并按最终接口规范明确协议、寻址、认证及传输保护要求。通信中断、请求超时、接口不可达和模型工件传输失败应能够被识别、记录并关联到相应机构和任务；恢复及重试策略应与业务幂等和任务状态要求一致。具体带宽、传输容量、响应时限和峰值指标应由项目指标及部署条件确认，不从现有 PDF 文件传输要求直接套用。

## 通信关系

下列 C01—C04 是本图的关系标记，不替代总稿的正式需求标识。箭头表示业务调用发起方向，而不是所有网络数据包的方向；应答及文件下载内容按相应请求返回。

| 标记 | 发起方 → 接收方 | 信息与用途 | 通信范围及约束 |
| --- | --- | --- | --- |
| C01 | 云端平台 → 指定医院运行时代理 | 训练任务、轮次指令、配置及初始模型引用，返回相应接收或执行确认。 | 跨域；平台应能受控访问该医院代理的业务端点，不假定仅有医院出网即可满足。 |
| C02 | 医院运行时代理 → 云端平台及约定工件访问端点 | 状态、指标、元数据和模型更新提交；模型工件获取或上传及相应结果。 | 跨域；工件下载由医院发起请求、内容随响应返回，不能误读为平台主动推送所有模型文件；图中不预设独立存储服务。 |
| C03 | 医院代理 ↔ 本地训练引擎 | 任务协调、执行状态与结果获取。 | 院内；引擎按任务启动，通信方式与生命周期匹配，不将引擎对其他医院直接开放。 |
| C04 | 本地训练引擎读取本院数据 | 授权训练样本及必要数据描述。 | 院内；本地文件读取不等同于跨网接口，不要求将本地数据源公开为网络服务。 |

院内读取线用于表达数据边界，不表示全部本地读取都采用网络协议。模型工件关系涵盖传输需求，不表示任何自动发布或医院个性化算法已经实现。云端业务推理及孪生应用的数据交互不属于本联邦通信子图，按总体系统通信要求另行描述。

## 待明确的通信指标

拓扑图不能代替以下可验证要求，最终总稿应补充对应指标及确认依据：

| 指标类别 | 应明确的内容 |
| --- | --- |
| 接入与协议 | 医院与云端的接入方式、业务端点可达方向、应用传输协议、安全接入与传输保护要求。 |
| 信息容量 | 控制请求与元数据容量、模型工件典型及最大大小、更新频率，以及上传与下载的不同需求。 |
| 链路与并发 | 医院侧上／下行能力、平台侧汇聚能力、同时训练及传输机构数、轮次集中上报峰值。 |
| 时间限制 | 控制接口响应时限、模型工件传输时限、状态与监测信息时效、中断识别及恢复要求。 |
| 异常诊断 | 超时、不可达、失败原因记录、传输完整性验证、任务关联、重试和重复提交处理要求。 |

上述内容是需完善项，不是已经确认的验收数值。网络产品、实际地址、端口映射和实施规则在软件设计及部署文件中落实。
