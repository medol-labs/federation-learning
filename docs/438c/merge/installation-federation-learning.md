## 联邦学习子系统部署

联邦学习子系统包含平台服务、共享支撑服务、管理控制台、参与方运行时代理及按训练需要启动的训练引擎。平台部署在中心侧，代理部署在各参与方环境，不能将所有容器默认放在同一主机。实际服务地址、证书、镜像仓库和持久卷路径由目标环境的部署清单确定；安装前应确认跨域网络连通性与访问策略。

### 安装前准备

准备与目标 CPU 架构一致的应用镜像及 PostgreSQL、UmaDB 等依赖镜像。离线环境先校验镜像包、版本和摘要，再导入目标节点。为平台、支撑服务和每个参与方代理分别规划事件存储、查询库及持久卷；参与方另需挂载本地数据目录，供代理读取数据集。模型工件及上传文件目录也应具备持久化与备份策略。

为每个部署单元填写其配置文件：数据库和事件存储连接、服务间可达端点、认证凭据、前端 API 地址及运行时数据目录。内部服务令牌、数据库口令和签名密钥应由现场安全配置提供，不写入镜像或交付文档。参与方数据目录在代理容器内应挂载到约定的读取位置；训练引擎使用的宿主机路径与容器路径需要分别核对。

### 部署与验证

（1）在各部署环境先启动 PostgreSQL 和 UmaDB，确认容器健康、持久卷可写及服务名可解析。

（2）启动共享支撑服务与平台服务，检查健康状态和事件存储连接。再启动管理控制台，确认浏览器可以访问对应后端。

（3）在参与方环境启动运行时代理，检查其本地查询库、事件存储、数据目录和平台端点配置。确认代理向平台报告连接与就绪状态。

（4）使用测试组织、特征架构和本地测试数据完成一次最小训练链路：作业提交、计划分发、代理执行、模型更新上报、聚合及模型目录查询。

Docker Compose 部署可先运行 `docker compose config` 检查变量和挂载，再运行 `docker compose --env-file .env up -d`，用 `docker compose ps` 与 `docker compose logs` 核验。K3s/Kubernetes 部署应使用现场镜像仓库、命名空间、Secret、持久卷和服务发现配置；不要沿用开发机的 `localhost` 地址。训练引擎由代理按作业需要启动，不应把本地训练数据复制到平台容器内。

### 故障恢复

遇到连接失败，先确认目标主机可达、端口与证书/令牌配置，再检查事件存储及数据库健康状态。事件消费或查询视图异常时保留持久卷和日志，不通过删除数据重试安装。恢复时先验证事件可读，再确认各服务的消费位置和查询视图可继续更新；模型工件和数据集文件需与其引用记录一同核对。升级与回退按部署单元逐步执行，并保留升级前的事件、查询库和文件存储备份。
