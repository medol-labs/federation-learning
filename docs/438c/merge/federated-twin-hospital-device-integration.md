## 建议正文

联邦孪生软件平台面向示范医疗机构，与院内既有信息系统及检测、监测设备开展标准化接口集成，按授权获取患者档案、诊断信息、治疗计划及检查检验、影像等诊疗信息；通过本项目建设的监测与可穿戴设备接入能力，采集生理信号和健康监测指标。接入过程完成身份与访问校验、患者标识关联、信息格式转换、质量校验及增量同步，按约定的数据使用范围进行传输和存储。诊疗及监测信息的同步频率和实时性以实际接口协议及设备能力为准，平台不改造医院原有系统的业务功能。

经授权接入的信息用于医疗数字人的患者状态展示、预测与仿真，以及疾病风险动态评估、预警和个性化健康管理。用于联邦协同建模的数据在机构本地按训练用途进行筛选、整理和绑定，由机构运行代理协调本地引擎完成训练与验证。联邦学习平台负责训练任务编排、模型更新聚合与质量验证，各机构向平台提交模型更新、训练验证指标及数据集元数据，不跨机构汇聚原始病例和患者明细。训练形成的模型工件下载后由应用推理侧部署，支撑相应业务应用。

## 接入对象与边界

| 对象 | 交互信息 | 接入方式与约束 |
| --- | --- | --- |
| 院内既有 HIS、EMR、LIS、PACS 等信息系统 | 患者档案、诊断、治疗计划、检查检验结果与影像信息。 | 按院内系统实际开放的标准化接口集成；不要求改造原业务功能，不假定所有系统已经开放全部数据。 |
| 院内检测与监测设备 | 检查检验结果、影像或生理检测信息。 | 根据现有能力，经院内业务系统或设备接口接入；同一结果不应因两条接入路径重复入库。 |
| 本项目监测与可穿戴设备 | 生理信号、健康监测指标。 | 设备接入、采集和传输属于本项目建设内容，按患者关联及授权规则使用。 |
| 机构侧接入与本地数据处理 | 授权的诊疗、检测与监测信息。 | 按用途处理、同步和存储；不替代医院原有系统，不默认建立全平台共享患者库。 |
| 医疗数字人与风险动态评估 | 经授权的诊疗及监测信息、患者状态和诊疗特征。 | 在院内或经批准的业务环境使用，不能将模型更新可出域理解为患者信息可任意出域。 |
| 机构本地训练与联邦学习平台 | 本地读取训练数据；跨机构协作交换模型更新、指标和元数据。 | 原始训练数据不出域；训练数据整理、原始数据使用与业务信息接入分别受相应授权约束。 |

“实时采集、传输与存储”应作为具体接口的时效要求单独确认，不能仅凭业务关系图认定全部既有系统已支持实时推送。“跨机构数据业务流转”改为“跨机构模型协作与授权业务信息使用”，避免与原始训练数据不出域相矛盾。
