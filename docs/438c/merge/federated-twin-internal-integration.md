# 联邦孪生平台系统集成关系

![系统集成关系](../../generated/diagrams/mermaid-diagram.png)

[原生 draw.io 图稿](../../mermaid-diagram.drawio) · [矢量图](../../generated/diagrams/mermaid-diagram.svg)

本图细化三大业务模块之间的集成关系，机构本地节点作为协同训练交互对象一并展示，不表示服务器或网络拓扑。图源沿用历史名称 `docs/mermaid-diagram.drawio`，但不由 Mermaid 维护；导出 PNG、SVG 位于 `docs/generated/diagrams/`。

布局按业务职责划分为左侧“联邦训练协作侧”和右侧“孪生业务应用侧”。左侧组织各机构本地执行与平台协作，右侧由应用推理服务支持医疗数字人及风险评估，两侧以模型工件交付连接。用户置于底部，业务结果使用与人工反馈分别走独立路径。分区不表示机构节点与平台共用环境，也不表示跨系统共享服务或数据库。

## 交互内容与职责

| 提供方 → 接收方 | 交互内容 | 职责与边界 |
| --- | --- | --- |
| 联邦学习平台 → 各机构本地节点 | 训练任务、初始模型、训练配置与轮次指令。 | 机构运行代理协调本地引擎执行训练与验证，各节点分别接收任务。 |
| 各机构本地节点 → 联邦学习平台 | 模型更新、训练验证指标、数据集元数据。 | 原始训练数据保留在各机构，不向联邦平台传输患者明细。 |
| 联邦学习平台 → 应用推理侧 | 可下载的模型工件、模型版本及必要配置。 | 下载后由应用推理侧部署，不表示联邦平台直接提供业务在线推理接口，也不表示已有自动部署能力。 |
| 医疗数字人 ↔ 医学业务模型与推理服务 | 业务推理请求与患者状态预测、仿真结果。 | 应用侧按场景加载模型；模型可来自联邦训练，也可由外部提供。 |
| 风险动态评估与管理 ↔ 医学业务模型与推理服务 | 业务推理请求与疾病风险评分。 | 推理执行与风险评估业务分工明确，业务模块负责结果解释、预警及管理。 |
| 医疗数字人 → 风险动态评估与管理 | 授权的患者状态、诊疗特征。 | 信息在相应授权范围内用于风险研判，不由联邦学习平台中转患者信息。 |
| 风险动态评估与管理 → 医疗数字人 | 风险评估结果、预警信息。 | 用于患者状态展示及临床业务协同。 |
| 医疗数字人 → 临床医生、科研人员 | 患者状态预测与仿真展示结果。 | 用户使用结果并观察实际效果，不表示系统自动执行应用验证或评审。 |
| 风险动态评估与管理 → 临床医生、科研人员 | 风险评估结果、预警与管理建议。 | 支持用户进行业务研判及使用效果观察。 |
| 临床医生、科研人员 → 联邦学习平台相关人员 | 使用反馈、发现的问题与模型优化建议。 | 由人员沟通、确认后作为后续训练与验证的依据；不表示已提供反馈接口、独立评审功能或自动重训。 |

蓝色实线表示业务信息及结果呈现，绿色实线表示模型工件交付，棕色虚线表示用户使用反馈与优化建议的人工沟通关系。临床医生、科研人员是使用角色，不是系统模块；反馈由相关人员确认，不要求系统提供专门的评审、反馈管理或自动采集功能。双向推理线分别代表请求与结果，不表示两侧共用用户、存储或支撑服务。

本图聚焦内部业务协作，院内既有系统集成及本项目可穿戴设备接入范围见[总体业务架构](federated-twin-business-architecture.md)，不在此重复展开。

## 编辑与导出

使用 draw.io 编辑 `docs/mermaid-diagram.drawio`，在项目根目录执行：

```bash
python3 docs/diagrams/drawio.py format docs/mermaid-diagram.drawio
python3 docs/diagrams/drawio.py check docs/mermaid-diagram.drawio
python3 docs/diagrams/drawio.py export docs/mermaid-diagram.drawio
```

只提交图源并同步维护本文交互说明，PNG、SVG 是已忽略的生成产物。图形使用[统一图库与工具](../../diagrams/README.md)，节点、连接线、标签均可在 draw.io 中继续编辑。
