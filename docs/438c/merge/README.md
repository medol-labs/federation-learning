# 3.3.1 联邦学习平台模块功能需求合并稿

本目录维护总需规 `3.3.1 联邦学习平台模块配置项功能需求/LBLS-GN-LBXX` 的 Markdown 中间稿，不修改或替代总需规 Word 原件。

## 文件与版本

- `3.3.1-federation-learning.md`：用于并入总需规的完整章节初稿，包含功能划分表及逐项需求正文。人工修改只在此文件进行。目前为 `0.1-draft`，尚未宣称是总需规的已批准版本。
- `3.3.1-function-register.json`：功能标识与当前建模切片的映射。`sourceId` 用于跟踪来源；`LBLS-GN-LBXX-Fxxxx` 是合并后的稳定标识，不能因排序或改名而复用、重编。
- `requirements-overview-corrections.json`：总需规原稿中联邦学习模块概述的受控修订。按原文逐段精确匹配，原稿变化时合并停止，避免重新生成后恢复不准确描述。
- `docs/generated/438c/merge/3.3.1-candidate.md`：按最新建模重建的完整候选章节，不包含人工稿的修订，供逐项对比。
- `docs/generated/438c/merge/3.3.1-final.md`：由人工稿按交付格式重排的 Markdown 快照，逐项包含用户故事及输入、处理、输出三部分；不在此文件中人工修订。
- `docs/generated/438c/merge/3.3.1-federation-learning.docx`：由交付格式快照导出的 Word 章节，可用于复制到总需规。此文件是导出物，不在 Git 中维护。
- `CHANGELOG.md`：经人工审核的合并版本及变更原因。Git 提交保存每版正文和映射；Word 仅在合并进入总需规时作为交付快照生成。

`3.3.1` 是总文档中的章节号；本稿标题不固定章节号，以免嵌入时冲突。表格“序号”按当前展示顺序连续编号，不作为追踪键。表号、图号及交叉引用由总文档统一编号。本稿不沿用来源 PRD 的 `5.x`、`6.x` 或 `FLP-PRD-SECTION-n` 编号。

## 范围与待核对事项

本稿依据当前 `.medol/codegen-model.json`，覆盖联邦学习业务能力及其部署所需的全部共享支撑上下文，共 15 个上下文、192 项功能。共享支撑部分包括字典维护、文件上传、系统通知、数据交换和身份访问管理。

- 共享支撑能力在本节给出与联邦学习部署相对应的需求及稳定标识；总需规其他模块如使用同一能力，应引用这些标识，避免复制出冲突的要求。
- `docs/438c/sources/prd.zh-CN.md` 和 `.medol/prd-use-cases.json` 必须从同版模型刷新。前者供完整需规生成，后者供本章节变更核对与候选稿生成；模型变更后旧快照不可沿用。
- “安排下一训练轮次”不单独产生结果记录；章节按现有业务流程说明其完成后自动发起下一轮参与者选择，最终结果由参与者选择功能承担。
- 当前 Markdown 已包含逐项角色、输入、业务约束、成功/异常结果、验收情形及查询内容。技术实现细节不自动照搬到交付正文；未建模的性能指标、接口细节和测试方法仍需评审，不得将 `0.1-draft` 当作已批准交付稿。

## 更新流程

1. 更新建模及 `.medol/codegen-model.json` 后，按 [438C 来源更新步骤](../README.md) 刷新 `.medol/prd-use-cases.json` 和中文 PRD；执行 `node scripts/prepare-438c-331.mjs --check`。脚本校验快照源哈希和用例覆盖，报告新增、缺失或内容变化的功能，并检查稳定标识和表内序号。
2. 审核这些变化后执行 `node scripts/prepare-438c-331.mjs --sync`。此命令更新映射并生成完整候选章节；当新增内容均属于新上下文时，只追加新增章节，不覆盖人工合并稿中的既有功能正文。其他变化仍需逐项人工合并。
3. 逐项比较候选稿与 `3.3.1-federation-learning.md`，只接受确认过的变化。记录在 `CHANGELOG.md`，重新检查并提交 Git。
4. 执行 `node scripts/prepare-438c-331.mjs --word`，从人工稿生成交付格式 Markdown 和可复制的 Word 章节；并入总需规的 01 Word 也使用同一排版转换。每项需求先呈现用户故事，在“需求说明”下用正文概述业务动作、关键约束及预期结果，再以“（1）输入”“（2）处理”“（3）输出”组织细项。用户输入按示例使用“字段名称、输入形式、可修改、默认值、内容及规则、必填”六列表；自动触发功能另列系统输入表；输出使用带表题的结果表。若代码生成模型明确标注字段来源，导出时在“内容及规则”中写明来源；没有明确来源的字段仍按原类型说明处理。来源不单独决定界面控件或可修改性。源稿未明确的默认值不推断，控件形式仅在类型足以判断时填写，否则标为“未指定”。处理部分列出权限要求、处理逻辑及异常处理。导出时将“表 3 联邦学习模块的软件功能划分”编号为 `3.3.1.1`，其后业务分组从 `3.3.1.2` 起依次编号，不再单列“功能描述”标题；人工 Markdown 不写入这些章节号，稳定功能标识也不变。并入总需规时再统一核对表号、Word 样式和交叉引用。

新增标识递增分配；被删除的来源功能须经人工决定是否废止，相应 `LBLS` 标识不得重新分配给别的功能。
