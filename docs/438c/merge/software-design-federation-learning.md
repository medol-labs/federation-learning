联邦学习子系统按平台、参与方运行时代理和共享支撑服务划分职责。平台接收组织、联邦、特征架构、训练配置和训练作业的操作请求；参与方代理接收执行计划，在本地读取数据集并驱动训练引擎。原始训练数据不作为跨域输入，跨域传递的是元数据、执行计划、模型更新及其工件引用。

| 输入或条件 | 处理决策 | 输出或异常结果 |
| --- | --- | --- |
| 组织加入联邦、运行时接入 | 先确认组织资格与运行时状态，再纳入可选参与范围 | 成员资格、运行时身份及连接状态分别记录；不满足条件时保留失败原因 |
| 特征架构与数据集声明 | 平台发布特征定义；参与方按定义检查本地文件和标签列 | 平台接收数据集元数据与合约结果，不接收原始样本 |
| 提交训练作业 | 使用已确定的训练运行配置，按参与方资格和最小节点数选择运行时 | 产生轮次、参与方执行计划；数量不足时记录选择失败，允许条件变化后重试 |
| 参与方训练完成 | 本地训练引擎生成模型更新与指标；代理上报工件引用 | 平台评估更新，拒绝不合格提交；满足聚合条件后形成全局模型 |
| 跨服务调用失败 | 保留失败状态与原因，重试由相应业务操作触发 | 不把网络错误伪装为训练成功，也不以查询投影的即时可见性作为命令成立前提 |

上述状态变化通过事件记录，查询视图异步更新。因此命令受理和页面列表刷新之间允许有短暂间隔，交互界面应明确展示处理中、失败与可重试状态。服务间认证由部署配置提供；平台令牌不自动赋予参与方本地账户权限。

联邦学习的数据对象分为组织与联邦、运行时、数据集与特征架构、训练与模型四组。组织加入联邦后，通过运行时身份与连接记录进入参与范围；特征架构约束参与方本地数据集；训练运行配置引用初始模型与特征架构，训练作业下包含轮次和参与方执行计划；模型更新经评估与聚合后形成新的模型制品。

平台、参与方代理分别维护自己的业务状态和查询视图。共享支撑服务维护字典、文件及平台侧身份数据。参与方原始数据集和本地执行状态保留在参与方侧，不合并为平台数据库表；同名身份功能部署在不同服务时也不表示共用用户库。

各部署单元分别使用 PostgreSQL 保存本服务的查询视图与处理位置，使用 UmaDB 保存业务事件。容器或本地启动时通过各服务自己的连接配置接入相应存储；平台与参与方不直接共享数据库连接。事件存储的持久卷、PostgreSQL 数据卷及备份范围应按部署单元单独定义。

查询表由服务内的持久化实体映射，字段类型以实际生成实体和迁移结果为准。标识字段使用相应的 UUID 或业务键类型；时间、数值和长文本不得为了统一而强制转成短字符串。经常按作业、轮次、运行时、组织或状态筛选的目录，应结合实际查询条件建立索引，并以真实执行计划验证。

业务事件追加与查询视图更新存在异步间隔。发生投影失败时应保留事件与处理位置，修复后重放或继续消费；不能通过直接修改查询表代替业务命令。备份与恢复必须覆盖事件存储和各服务查询库，并验证事件重放后的视图一致性。全系统“单一主数据库”或固定数据库产品的描述不适用于本子系统。

<!-- INSERT architecture -->

联邦学习由平台服务、参与方运行时代理、共享支撑服务、前端控制台及按需启动的训练引擎组成。部署拓扑由实际网络与节点位置决定：平台和参与方可以位于不同网络域，不能把开发机回环地址作为跨节点通信地址。

| 部件 | 主要职责 | 持久化或外部依赖 |
| --- | --- | --- |
| 平台服务 | 组织与联邦管理、特征架构、训练编排、模型治理、安全聚合及运行时监控 | 平台事件存储、查询库；运行时代理接口 |
| 参与方运行时代理 | 本地数据集登记与验证、执行计划接收、训练作业启动和结果上报 | 参与方事件存储、查询库、本地数据目录、训练引擎 |
| 共享支撑服务 | 字典、文件与平台侧账户权限等共用能力 | 支撑服务自身的存储和文件目录 |
| 前端控制台 | 呈现管理、查询、操作及状态反馈 | 通过受保护接口访问相应后端 |
| 训练引擎 | 按执行计划完成本地训练或模型聚合任务 | 输入数据或模型工件、输出更新与指标文件 |

平台根据已登记的运行时端点向具体代理分发任务；代理向平台报告连接状态与本地模型更新。平台与代理之间的调用通过服务身份认证，普通用户权限仍由各部署单元分别验证。共享支撑能力不等于跨域共享数据库。

<!-- INSERT execution -->

平台侧先准备联邦成员、运行时、特征架构、初始模型和训练配置。训练作业提交后选择满足条件的参与运行时，对每个运行时生成并发送执行计划。参与方代理校验计划和本地数据集，接受后按需启动训练引擎；训练引擎结束时代理读取作业结果和模型更新工件，并向平台报告。

平台评估收到的更新；达到所需参与数量后执行明文或安全聚合分支，形成全局模型并评估本轮结果。尚需继续训练时，以本轮结果作为下一轮输入重新选择参与方；达到结束条件后登记最终模型。运行时失联、训练失败、更新被拒绝或聚合失败分别保留原因，补偿和重试不得生成另一条无法关联的轮次链。

参与方运行时引擎不是常驻业务服务。代理在需要训练或聚合时准备其运行环境、提交作业、观察结果并释放资源；执行环境可由本地容器编排提供，跨节点部署时使用目标环境可达的服务地址及数据卷映射。

### 联邦学习模块性能设计

训练作业提交与跨节点训练完成是不同时间尺度。用户操作接口应尽快返回已受理结果，训练进度通过轮次和执行状态查询；不能将模型训练、跨节点等待或聚合全部压在一次同步 HTTP 请求中。前端对投影延迟显示处理中状态，避免把暂未查询到视为失败。

运行时代理数量增加时，平台按目标运行时分别分发执行计划，并以每个计划的状态和最小参与节点数控制后续阶段。查询侧按组织、作业、轮次及状态设置可用索引，使用数据库条件查询与分页，避免全表取出后在应用内过滤。事件消费线程数、批量大小和轮询保底参数应随存储与节点容量测量后配置。

训练耗时受模型、数据量、轮数、网络和参与节点数量影响。当前设计不承诺未经压测验证的固定响应时间、吞吐量或并发数；交付验收指标须在目标硬件、网络拓扑和数据规模确定后由性能测试说明给出。

### 联邦学习模块接口设计

| 接口方向 | 交换内容 | 设计约束 |
| --- | --- | --- |
| 控制台到平台及支撑服务 | 管理命令、目录查询、文件上传与模型信息 | HTTP 接口鉴权；命令受理与查询视图更新分离 |
| 平台到参与方代理 | 参与方执行计划及运行时操作请求 | 按运行时端点目录选择目标；使用部署配置的服务凭据 |
| 参与方代理到平台 | 连接与就绪报告、数据集元数据、模型更新提交 | 保留训练作业、轮次、运行时和工件标识以关联结果 |
| 参与方代理到训练引擎 | 作业提交、状态查询、结果读取及资源释放 | 仅传可访问的本地数据/模型位置和任务参数；按作业标识跟踪 |
| 平台到共享支撑服务 | 文件工件上传、下载与引用管理 | 工件标识与业务状态分开管理，不在事件中保存大文件原文 |

实际接口地址、TLS 与认证参数由部署环境配置，不写入设计正文。外部系统的网络连通性、信任边界和访问策略应与部署拓扑共同评审；平台可访问代理端点不意味着浏览器可以直接访问该代理。

联邦学习的详细设计按职责链组织。平台的训练编排负责训练作业、轮次、参与者选择、计划生成和分发；参与方代理负责本地验证、引擎执行和更新提交；模型仓库管理初始与聚合后的模型工件引用；安全聚合和明文聚合为不同处理分支。每一步的业务结果以事件记录，独立查询视图用于页面和调度观察。

| 处理单元 | 关键输入 | 主要输出与失败处理 |
| --- | --- | --- |
| 参与者选择 | 联邦成员、运行时身份、数据集资格、特征架构与最小节点数 | 选中运行时清单；不足时记录失败并允许重试 |
| 执行计划生成与分发 | 轮次、目标运行时、基础模型工件和训练配置 | 每个目标运行时一份计划；逐个记录分发结果 |
| 本地执行 | 执行计划、本地数据集、训练引擎配置 | 引擎作业标识、进度、模型更新与指标；启动和运行失败分别记录 |
| 更新评估与聚合 | 已提交的模型更新、轮次配置和聚合要求 | 接受或拒绝更新；满足条件后产生全局模型工件 |
| 轮次完成与后续调度 | 全局模型评估、轮次预算和继续条件 | 下一轮计划或最终模型登记；失败时保留当前轮次状态 |

一次执行计划、引擎作业、模型更新提交及平台轮次应通过各自标识关联。代理观察引擎作业时，运行中、完成、失败结果必须与轮次状态转换一致；重复观察不得反复创建新的轮次执行记录。异常恢复以已有标识重试或补偿，不以随机新标识掩盖已发生的业务结果。
