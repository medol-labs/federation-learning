联邦学习操作分平台侧准备、参与方本地准备、训练执行和结果查看。操作人员登录各自有权访问的界面；平台侧账户权限不能直接替代参与方本地授权。页面提交操作后，系统可能先显示已受理，再由后台更新目录状态；遇到短暂未刷新时应查询作业或轮次状态，不要连续重复创建业务对象。

#### 平台侧准备

（1）注册组织并建立联邦，邀请和批准参与组织。确认组织、成员资格及运行时身份在相应目录中可见。

（2）登记运行时基础设施或确认人工安装的运行时代理已经连接、就绪。平台管理员核对实际可达的代理端点，不把浏览器地址或本机回环地址当作远程代理地址。

（3）定义并发布特征架构，确认特征列、标签列、版本和适用范围。登记初始模型工件，确认模型文件可读取。

（4）定义训练运行配置，选择特征架构、初始模型、轮次预算与每轮最少参与节点数；核对配置后提交训练作业。

#### 参与方本地准备

（1）在运行时代理可访问的目录准备数据文件，仅向平台报告必要的元数据，不上传原始样本。

（2）声明数据集并配置运行时数据集绑定；核对特征架构与本地文件列名、标签列相符。

（3）执行本地访问验证、数据集分析和合约验证。失败时查看失败原因，修正路径、权限或列结构后执行对应重试操作。

（4）确认参与方运行时已连接且具备训练所需资源，再等待平台分发执行计划。

#### 查询与定位

在目录或仪表板中选择业务标识、名称、状态、时间等页面提供的条件后执行查询。不同字段同时填写时结果须同时满足这些条件；状态选择多个值时可查看任一所选状态。列表显示当前条件下的总条数，并可排序、翻页；更换条件后从第一页查看，清除条件可恢复未筛选列表。无结果时先核对条件与本人可见范围，不要据此判断记录已删除。

平台侧可按联邦或训练作业定位作业仪表板，再查看参与者资格与各轮进度；参与方在本地按数据集或训练作业定位就绪状态与轮次执行记录。查看失败记录时核对阻止原因、缺失要求或重试原因。模型目录查询仅用于定位工件，下载仍需使用有权限的下载操作。离开页面再返回时应核对保留的条件，避免误以为当前列表包含全部记录。

命令显示已受理而列表尚无新记录时，使用页面的重新查询操作并查看处理中状态；若显示业务失败则依据失败原因处理。查询接口出错时保留条件重试，不连续重复提交创建或训练命令。参与方只能查看本地获授权的数据，平台管理员也不能通过目录检索参与方原始样本。

#### 训练与结果

训练作业提交后，平台选择参与方、生成并分发每个运行时的执行计划。参与方接受计划后启动本地训练引擎；页面可分别查看作业、轮次、参与方执行和模型更新的状态。若参与节点不足，查看选择失败原因，补足就绪条件后重试选择，不要重新创建一份无法关联的训练作业。

本地训练完成后，代理上报模型更新工件。平台评估更新，达到本轮条件后聚合并评估全局模型；尚未达到轮次结束条件时继续下一轮。最终模型在模型目录中查看和下载。模型文件应通过受授权的工件下载操作获取，不能仅凭页面上的引用字符串作为可用文件。

多中心联邦建模由平台管理员和参与方管理员协同完成。平台先建立联邦、特征架构、初始模型和训练配置，参与方分别接入运行时并准备本地数据集。平台提交训练作业后按资格与最少节点数选择运行时，将计划发送到各参与方；每个参与方只读取自己的数据并返回模型更新。平台评估、聚合和发布全局模型，全程不集中收集原始病例数据。

若某参与方拒绝计划、运行时离线或数据集校验失败，先在对应目录查看失败原因，由负责该节点的操作员修复并按状态重试。若模型更新不足以达到本轮条件，训练作业保留当前进度；达到条件后才进入聚合及后续轮次。跨机构结果以训练作业标识和轮次标识追踪，不以重新创建作业代替故障恢复。
