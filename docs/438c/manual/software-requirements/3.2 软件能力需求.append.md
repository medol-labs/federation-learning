#### 身份访问管理的双实例需求

身份访问管理的用户账户、角色、权限和服务账户令牌能力按一组共性功能要求描述，不因部署两次而重复计算功能项。系统分别部署平台侧实例和参与方侧实例，两者的身份与授权数据属于不同作用域。

| 部署实例 | 使用范围 | 身份与授权数据边界 |
| --- | --- | --- |
| 平台侧 IAM（PlatformIam） | 由支撑服务承载，管理平台侧账户、角色、权限和服务账户令牌；平台业务服务使用经验证的身份与权限访问业务接口 | 以支撑服务的身份数据为准 |
| 参与方侧 IAM（ParticipantIam） | 由运行时代理承载，保护参与方本地接口及本地资源操作 | 以该运行时代理的本地身份数据为准；不同代理之间也不默认共享 |

- IAM-DEP-01：两处实例遵循相同的账户、角色、权限和令牌功能规则，但各自的账户停用、角色分配及权限变更仅在本实例作用域内生效。
- IAM-DEP-02：平台侧账户或令牌不能仅因已在平台侧创建就视为运行时代理的本地用户。访问参与方接口仍须通过该代理的身份验证和授权；服务间调用使用明确配置的服务凭据。
- IAM-DEP-03：当前范围不包含两处 IAM 数据的自动同步或统一账户生命周期。若要求同一用户跨平台与参与方无感登录，应另行规定身份联邦、信任配置和权限映射，不得从“共用 IAM 能力”推断已经实现。

验收时应分别验证两个作用域的账户停用和权限变更，并验证未携带有效凭据的跨服务请求被拒绝。
