## Flow

```text
CodegenModel
  -> DeploymentModelBuilder
  -> EnvironmentResolver
  -> Docker Compose / Kubernetes / K3s / APISIX renderers
```

Commit `operations-model.json` as the portable deployment model. Configure deployment settings in `operations/config/common.yml` and environment-specific settings in `operations/config/<environment>.yml`. Put machine-specific registry settings in the ignored `operations/config/<environment>.private.yml`. The generated `operations-model.private.json` is also ignored; the image script reads it for its default registry prefix.

## Image Bundle Command

Use `images.mjs` to orchestrate generated backend, frontend, and infrastructure images from this monorepo:
Build/export names use the portable model prefix, independent of Registry configuration. Push retags verified local images to the Registry destination. Use --prefix / DOCKER_IMAGE_PREFIX only to override the local source name; use --push-prefix / DOCKER_PUSH_IMAGE_PREFIX for the push destination.
For offline K3s delivery, `node operations/scripts/package-offline.mjs --help` describes the generic packager. It collects existing archives and renders the selected environment with optional project components; it never builds or pulls images.

```bash
node operations/images/images.mjs list --environment <environment>
node operations/images/images.mjs all --environment <environment>
node operations/images/images.mjs build --environment <environment> --exclude-service <service>
node operations/images/images.mjs build --environment <environment> --service <backend-module>
node operations/images/images.mjs push --environment <environment> --prefix registry.example.com/team
node operations/images/images.mjs push-dependencies --environment <environment> --prefix registry.example.com/team
node operations/images/images.mjs import --environment <environment>
```

Application image builds use the native Docker platform by default. Pass `--platform linux/amd64` or `--platform linux/arm64` only when you intentionally need a fixed target architecture; cross-architecture frontend builds can be much slower.

Use `--service` to process only selected application services, or `--exclude-service` / `--skip-service` to skip selected services during development.

When pushing dependency images for K3s registry mirrors, application images use `--prefix` as a registry namespace, while dependency images default to the registry root. For example, `--prefix registry.example.com/team` pushes `postgres:16` to `registry.example.com/library/postgres:16` so containerd mirror rewrites can resolve the original image path.
